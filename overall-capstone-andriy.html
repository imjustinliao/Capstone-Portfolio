Overall Capstone Andriy Demyanyuk

Introduction

For my capstone project, I worked on building the backend for Serene, a mobile app designed to help people meet in real life instead of relying on endless messaging like many dating apps. The backend handles core functionality such as user authentication, storing profile data, managing matches, and connecting the mobile app to the database through APIs.

Beyond the technical work, the project was also an opportunity to experience what it is like to develop a larger system over time. I worked with a co-founder, Justin, who was building the iOS frontend, learned new technologies, and dealt with problems that did not have clear solutions. This made the project feel closer to real-world software development than most assignments I had completed before.

Project Motivation and Technology Choices

I chose this project because it allowed me to build something I was genuinely interested in while gaining experience with backend development. The concept behind Serene is to encourage real-life interaction rather than long messaging threads or endless swiping. I was interested in working on a system that tries to change how people interact with dating apps.

From a technical perspective, the project also gave me the chance to use tools that are common in real applications. I built the backend using Python and Flask to create API endpoints, and I used Supabase for the database and authentication. These technologies allowed the backend to communicate with the mobile application and manage user data efficiently.

System Design and Development Process

To make the project manageable, I divided it into smaller components. Instead of trying to build everything at once, I focused on individual parts of the system such as authentication, profile management, and the matching system. Once each piece worked independently, I connected them together.

Since the frontend was being developed separately in SwiftUI, I also had to make sure the backend APIs were structured in a way that the mobile app could easily use. This required thinking carefully about how data would be organized and how different parts of the system would communicate.

Keeping the code organized and documented was also important. Writing clear comments helped ensure that both developers could understand how different parts of the system worked.

Challenges and Collaboration

One of the most challenging parts of the project was designing the location-based matching system. Because the app focuses on real-life interactions, the backend needs to determine when users are physically close enough to potentially match. Handling location data required thinking about efficiency, accuracy, and user privacy.

Another challenge was integrating different technologies. Flask, Supabase, and the SwiftUI frontend all work differently, and connecting them sometimes created unexpected issues. Debugging these integration problems helped me better understand how full systems operate.

Working with a co-founder also taught me how important communication is in software development. Since the frontend and backend depend on each other, even small changes could affect the other part of the system. Staying aligned on design decisions was necessary to keep the project moving forward.

Conclusion and Future Work

Overall, building the backend for Serene was one of the most valuable experiences of my computer science program. It allowed me to apply concepts from my coursework while also gaining practical experience with system design and collaboration.

While the current backend supports the core functionality of the app, there is still room for improvement. Future work could include optimizing the matching system, adding additional safety features, and improving performance as the number of users increases.

Regardless of what happens with the project in the future, this experience helped me better understand the process of building a real software system and preparing for work as a software engineer.
